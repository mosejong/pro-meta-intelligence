# 구현 우선 진행 방식 · 2026-11-19

사용자는 기능마다 전체 검사를 반복하기보다 구현 속도를 높이고, 필요한 시점에 검증과 수정을 집중하라고 지시했다. 기존의 출처·권한·제품 공개 범위는 그대로 유지한다.

## 평소 진행

1. Claude Opus 5.5 medium은 소유 파일을 정해 작동하는 기능을 먼저 구현한다. Codex는 연결·범위 관리와 변경 부분의 짧은 확인을 맡는다.
2. 기능마다 타입/컴파일과 대표 동작을 확인한다. 데이터 유실·권한 누출·정책 우회처럼 즉시 고쳐야 하는 실패는 수정한 뒤 진행한다.
3. 이미 통과한 전체 검사는 새 실패나 연결 변경 없이 반복하지 않는다. 브라우저 전수·여러 팀 장기 검사는 통합 배치에서 묶는다.
4. 구현 완료·핵심 확인·통합 검증·공개 반영을 구분해 표시한다. 미검증 기능을 안전성/효용 입증으로 부르지 않는다.
5. 한도가 걸리면 작업을 보존한다. 예약 등록은 실제 실행 증거가 아니며 세션 결과와 수정 파일을 확인한다. 09:55 예약은 실행되지 않아 10:20 수동 재개했고, 중복 방지를 위해 해당 일회성 예약만 비활성화했다.

## 교차 검증을 확대하는 시점

- 공개 출시·배포 후보가 모였을 때
- 로그인·방 권한·저장 형식·서버 영속성의 큰 변경
- 새로운 원본/API·시점 누출·선수 ID 연결처럼 데이터 신뢰성 판단이 필요한 경우
- 실제 예측 성능·효용·인과 효과를 주장하기 전

그때 사용 가능한 Claude·Codex·다른 AI의 접근 권한과 한도를 확인해 구현자와 검토자를 나눈다. 같은 모델의 여러 세션을 서로 다른 모델의 검증으로 세지 않는다. 도구가 없는 서비스를 사용했다고 말하지 않는다. 외부 계정·비용·제품 공개 결정은 사용자 범위를 따른다.

현재 새 구현은 여러 동일 시드의 A/B 가정 비교다. 기존 추상 엔진을 재사용하며 실제 선수/챔피언 효과·실전 승률 계산을 추가하는 작업은 아니다.
