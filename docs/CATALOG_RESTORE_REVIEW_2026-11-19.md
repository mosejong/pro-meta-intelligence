## 결함 R1 — 늦은 수동 카탈로그 읽기가 보관함에서 복원한 카탈로그를 덮어씀

- 관련 연결: `web/app/roster-workshop.tsx:95`의 편집기 key는 basis와 팀 쌍이다. 같은 basis/팀 쌍의 보관함 복원에서는 기존 편집기와 그 아래 시즌 패널이 유지된다.
- `web/app/roster-workshop.tsx:153`에서 복원할 시즌 라인업을 검증하고, `:159`에서 저장 당시 카탈로그를 설정한 뒤 `:161-162`에서 라인업·현재 로스터를 설정한다.
- 그러나 같은 편집기의 `web/app/season-lineup-panel.tsx:28`은 unmount 때만 진행 중 수동 읽기를 취소한다. `:29-36`의 수동 읽기는 카탈로그가 다른 복원으로 설정되었는지 확인하지 않고 `onCatalog(parsed)`를 호출한다. 이 콜백은 `web/app/roster-workshop.tsx:307`의 `setSeasonCatalog`에 직접 연결되어 있다.
- `web/app/season-player-cards.ts:49-50`은 참조의 catalog_id와 현재 카탈로그가 다르면 참조 해석을 거부한다. 따라서 덮어쓰기 뒤에도 남은 보관함 참조는 더 이상 해석되지 않는다. `web/app/roster-workshop.tsx:200-207`의 저장 가능 시즌 구성도 null이 되어 선수 구성을 함께 저장할 수 없게 된다.

재현 조건 및 순서:

1. 시즌 카탈로그가 아직 없는 편집기에서 수동 ‘시즌 선수 자료 불러오기’를 시작하고 응답을 보류한다.
2. 같은 분석 basis와 같은 팀 쌍에 대해, 현행 카탈로그와 ID가 다른 보존 카탈로그를 사용하는 시즌 선수 포함 연습을 보관함에서 불러온다. 해당 보존 카탈로그가 정상 검증되어야 한다.
3. 수동 요청보다 보관함의 카탈로그 검증·복원이 먼저 완료되게 한다. 이때 저장 당시 카탈로그와 참조가 모두 정상이다.
4. 보류한 수동 요청에 현행 카탈로그를 반환한다. 진행 중 요청은 취소되지 않았으므로 현행 카탈로그가 복원 카탈로그를 덮어쓰며 기존 시즌 참조는 해석 실패한다.

팀 쌍/basis 변경으로 편집기가 unmount되거나, 두 카탈로그 ID가 같거나, 수동 요청이 먼저 완료되면 이 재현 조건에 해당하지 않는다. 구단 보존 카탈로그 읽기의 abort 결함으로 혼동하지 않는다.

독립 검사 `web/tests/catalog-restore-review.test.mjs:36`은 실제 `SeasonLineupPanel.load` 선언을 TypeScript AST로 추출해 실행한다. 로컬 현행 카탈로그에서 카드 하나를 제외하고 SHA-256을 재계산한 유효한 다른 카탈로그를 만들고, 실제 파서·무결성 검사·참조 해석기로 검증한다. 보류한 수동 읽기 중 복원 카탈로그를 설치한 다음 응답을 완료하면, 정상 해석되던 참조가 해석 실패함을 단언한다. 서버에 특정 과거 아카이브가 실제 존재한다는 주장은 하지 않는다.

수정 방향(미적용): 외부 복원으로 카탈로그가 설정될 때 기존 수동 요청을 무효화하거나, 수동 요청의 적용 시점에 시작 당시 카탈로그/복원 세대가 여전히 유효한지 확인한다. 단순히 버튼을 숨기는 것은 이미 시작된 요청을 취소하지 않는다.

## readyInput·탭간 변경의 판정과 한계

연결 확인을 위해 `draft-lab.tsx:273-276,753-759,863-874`와 `simulation-readiness-panel.tsx:134-150`을 읽었다. 연습 복원은 liveRoster를 철회하고 readiness 패널을 새 comparisonEpoch로 remount한다. 과거 시즌 선수가 보고된 동안 experimentReadyInput은 null이며, readiness 패널은 변경/cleanup 시 부모 입력을 갱신한다. 부모 readyInput을 복원 콜백에서 직접 지우지는 않으므로 효과 실행 전 전달 지연을 소스에서 볼 수 있지만, 그 사이 실제 사용자 실행이 가능한지는 이번 단위 검사로 확인하지 않았다. 이를 이전 readyInput 혼입 결함으로 집계하지 않았다.

구단 저장 변경은 실제 confirm 핸들러에서 저장본 재비교를 검사했다. 실제 StorageEvent 전달과 React layout cleanup 스케줄링은 브라우저 미사용으로 실행하지 않았다. 연습 IndexedDB read는 트랜잭션 시점의 사본을 반환한다(`draft-practice-library.ts:258-273`). 카탈로그 await 중 다른 탭에서 연습을 삭제/이름 변경해도 재조회하지 않지만, 읽어 둔 연습 사본 복원을 금지하는 계약이나 내용 손상 재현을 확인하지 못했으므로 별도 결함으로 세지 않았다.
