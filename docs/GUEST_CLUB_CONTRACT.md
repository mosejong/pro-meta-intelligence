# 게스트 구단 v1

2026-11-18. 로컬 비로그인 기능이며 운영용 계정·클라우드 저장과 구분한다.

## 사용자 흐름

`선수·로스터` 탭에서 블루/레드 선수 구성을 편집한 뒤 구단 이름을 붙여 저장한다. 최대 10개이며 감독·코치는 선택적으로 직접 적는 가상 구성 이름이다. 출처가 있는 코치 명단·공식 소속·능력치 기능은 아니다. 빈 자리도 그대로 저장한다.

불러오기에서 선택한 진영과 다섯 자리 미리보기를 확인한 뒤 적용한다. 취소는 편집을 유지한다. 상대 로스터와 선수 ID가 겹치거나 선수/자료 기준이 맞지 않으면 전체 적용을 거부하고 양쪽 로스터를 유지한다. 적용은 기존 로스터 편집/A·B 비교 입력 경로만 사용하고 밴픽·원관측·고정된 A·실제 승률을 바꾸지 않는다. 다른 진영에도 적용할 수 있지만 상대와 중복된 선수를 자동으로 옮기지 않는다.

삭제에는 확인이 필요하며 현재 로스터는 유지한다. 저장된 구단을 자동으로 덮어쓰지 않고 새 사본으로 저장한다. 현재 구단 이름이 실제 팀 이름을 대체하거나 실시간 방에 공유되지는 않는다.

## 저장 계약

- localStorage 키 `pro-meta-guest-clubs-v1`.
- `{artifact_type:'guest-clubs',schema_version:1,clubs:GuestClub[]}`.
- 구단: UUID v4 id, revision 1, 이름 최대 40자, 감독·코치 각 60자, 기준 팀 ID, RosterBasis, 역할별 선수 source_team_id/player_id 또는 null, 생성/변경 시각.
- 자료 기준은 패치·cutoff·fixture 여부·출처 버전으로 묶는다. 옛 기준의 구단은 보관/삭제할 수 있으나 현재 기준에 자동 변환하지 않는다.
- 전체 크기 768KiB, 최대 10개. 중복 선수 ID·중복 구단 ID·잘못된 역할·미지원 버전·손상된 내용은 거부한다. 손상 자료를 빈 목록으로 간주해 덮어쓰지 않는다.
- 모든 UI 쓰기는 같은 origin의 Web Locks 이름으로 직렬화하고 lock 내부에서 최신 목록을 읽는다. API가 없는 브라우저에서는 안전하지 않은 저장으로 우회하지 않고 안내한다. 읽기/쓰기 실패를 저장 성공으로 표시하지 않는다.
- 다른 탭 변경은 storage 이벤트로 목록을 갱신한다. 확인 중 내용이 바뀌면 적용/삭제를 멈춘다.

이 기기·브라우저 저장이며 사이트 데이터 삭제나 기기 교체 시 사라진다. OAuth owner ID·서버 인증·자동 계정 귀속·기기 간 저장·구단 파일 내보내기는 이번 구현에 없다. 기존 로스터 파일 기능은 유지한다. 사용자에게 JSON 편집을 요구하지 않는다.
