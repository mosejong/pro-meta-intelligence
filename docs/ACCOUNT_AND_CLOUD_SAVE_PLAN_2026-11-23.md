# 로그인·서버 저장 구성안 · 2026-11-23

[구단주·클럽 서비스 계획](OWNER_CLUB_SERVICE_PLAN.md) 6단계(계정·영속화)를 실제로 붙이기 위한 구성안이다. 계정 생성·키 발급·결제는 사용자 결정이며 이 문서로 실행하지 않는다.

## 지금 상태

- 공개 사이트는 GitHub Pages 정적 배포다. 구단·연습·복기·의견은 그 브라우저(localStorage/IndexedDB)에만 저장된다.
- 실시간 친구 방은 Node 서버 코드와 파일 영속성 검사가 있으나 운영 호스팅이 없다.
- 저장소에 Cloudflare Worker 진입점(`web/worker/index.ts`)과 `@cloudflare/vite-plugin` 빌드 설정이 이미 있다.

## 비교

| 항목 | A. Cloudflare Workers + D1 + Durable Objects (추천) | B. Supabase(DB·인증) + Pages 유지 | C. 자체 서버(VPS) + Postgres |
|---|---|---|---|
| 기존 코드와 맞음 | Worker 진입점·빌드 설정 있음 | 프런트에 SDK 추가 | 방 서버 코드 재사용 가능 |
| 실시간 방 | Durable Objects가 방 1개=객체 1개로 맞음 | Realtime 채널로 재설계 필요 | 지금 Node 방 서버 그대로 |
| 로그인 | Worker에서 OAuth code 교환(키는 Worker 비밀값) | 내장 Discord 지원, 카카오는 커스텀 | 직접 구현 |
| 시작 비용 | 무료 등급으로 시작 가능(한도는 가입 시 확인) | 무료 등급(일정 기간 미사용 시 일시정지 정책 확인 필요) | 월 서버 비용 + 관리 부담 |
| 1인 운영 부담 | 낮음(서버리스) | 낮음 | 높음(보안 패치·백업·장애) |
| 중국 접속 | 별도 확인 필요 | 별도 확인 필요 | 지역 선택 가능 |

가격·한도는 가입 시점의 공식 안내로 다시 확인한다. 이 표의 비용 칸은 계획 판단용이며 견적이 아니다.

## 추천: A

1. **1차(로그인 없이도 가치):** 기기 간 이어하기 코드. 구단·연습 보관함을 서버에 저장하고 짧은 복구 코드로 다른 기기에서 불러온다. 계정 없이 동작하고, 나중에 계정에 귀속한다.
2. **2차:** Discord 로그인(`identify`만) → 저장본을 계정에 귀속. 카카오는 앱 심사 요건 확인 후 추가.
3. **3차:** 실시간 친구 방을 Durable Objects로 이전해 공개.

## 사용자가 해야 할 것 (내가 대신하지 않음)

| 단계 | 할 일 | 필요 시점 |
|---|---|---|
| 1 | Cloudflare 계정 생성, Workers·D1 사용 설정, GitHub Actions용 API 토큰 발급 후 저장소 Secret 등록 | 1차 배포 전 |
| 2 | Discord 개발자 앱 생성, redirect URI 등록, client secret을 Cloudflare 비밀값으로 등록 | 2차 |
| 3 | (선택) 도메인 구매·연결. 없으면 `*.workers.dev` 주소로 시작 | 공개 홍보 전 |
| 4 | 개인정보 처리 안내의 운영자 정보 확정 | 로그인 공개 전 |

키·토큰은 대화에 붙여넣지 않고 GitHub/Cloudflare 설정 화면에서 직접 등록한다.

## 내가 먼저 할 수 있는 것 (계정 없이)

- 1차 API(저장·불러오기·복구 코드·용량 제한·만료·남용 제한)와 D1 스키마를 만들고 로컬 Miniflare에서 검사한다.
- 웹에 "다른 기기에서 이어하기" UI를 붙이되, 서버 주소가 설정되지 않으면 버튼을 숨긴다(지금 의견 메일 주소와 같은 방식).
- 배포 워크플로를 준비하되, Cloudflare 토큰이 등록되기 전에는 실행되지 않게 한다.
