# 사용 한도에 맞춘 자동 진행 · 2026-11-19

사용자 승인: 남은 사용량을 고려해 자동 개발을 이어가고, 부족하면 초기화 시각 이후 재개를 예약한다. 토큰을 많이 쓰는 것 자체가 목표는 아니다.

- 기존 automation-4를 매시 5분의 개발 재개 점검으로 갱신했다. 같은 스레드의 작업이 진행 중이면 중복 실행하지 않는다. 기존 10:45 역사자료·14:45 일정 복구는 별도이며 공급자 요청 간격을 유지한다.
- 실제 Claude 결과의 usage/modelUsage는 그 실행의 사용 기록이다. 계정의 실시간 잔량이 아니다. Codex와 Claude의 전체 남은 토큰을 모두 볼 수 있다고 말하지 않는다.
- 명시적 한도 오류를 받으면 해당 서비스 호출을 멈추고 오류·세션·진행 파일·초기화 시간대를 기록한다. 표시된 시각이 있으면 5분 뒤 한 번 재개하도록 예약을 바꾼다. 초기화가 추정되거나 재차 한도이면 반복 호출하지 않는다.
- 재개가 실제 성공하면 정기 점검으로 돌아간다. 초기화 시각이 없으면 해당 서비스의 호출은 보류하며 자동으로 임의의 재충전 시각을 만들지 않는다.
- 추가 과금·크레딧 전환·요금 변경·계정/모델 우회는 하지 않는다. Claude 구현/Codex 연결·핵심 확인의 분담, 제품 배포 보류는 유지한다.
- 예약 등록과 실행 성공을 구분한다. 09:55 일회성 예약은 실제 미실행이 확인돼 10:20 수동 재개했다. 원인은 미확인이며 이번 예약도 실제 다음 실행 결과로 확인해야 한다.

현재 작업은 연습 보관함과 로스터 복원의 연결 설계/구현이다. 완료한 기능을 다시 구현하지 않는다. 자동화 실행은 현재 체크포인트와 작업 상태 파일을 먼저 확인한다.
