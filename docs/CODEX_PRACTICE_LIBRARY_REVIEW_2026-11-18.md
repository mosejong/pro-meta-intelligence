Claude가 실행한 검사와 Codex가 독립 재실행한 검사를 구분해서 아래에 기록한다.


## 1차 독립 실행

- Codex가 관련 Node 6개를 재실행해 통과했다. 이것만으로 비동기 UI 보존을 검증하지 못한다.
- Codex 작성 브라우저 재현 `draft-practice-library-review.spec.mjs`: **실패 재현**. 저장된 1수 연습을 열기 전 현재 보드를 0수로 비운 뒤, library DB open을 1.2초 늦추고 읽는 중 새 챔피언을 올렸다. 늦은 복원이 명시 확인 없이 적용되어 progress가 0→1로 바뀌고 새 작업이 소실됐다.
- 구현은 Codex가 고치지 않고 동일 Claude 세션에 재현 절차·새 검사를 전달했다. 보관함 읽기 중 scenario/context 변경 및 잠금 전환 시 이전 확인의 부활도 함께 검토하도록 요청했다.


## 수정 후 독립 검증

- Claude에 재현을 돌려 `createPracticeLoadGate`와 board/lock revision 확인을 추가했다. 기존 재현 검사를 바꾸지 않고 PC·모바일에서 재실행해 통과했다.
- 실제 Chrome IndexedDB 두 탭에서 4개를 저장한 뒤 서로 다른 이름으로 동시에 마지막 자리를 저장했다. 양쪽 모두 실행을 마친 뒤 실제 store에는 5개와 단 하나의 승자만 있었고, 기존 4개 및 현재 밴픽은 보존됐다. 메모리 대역 결과를 실제 브라우저 검증으로 대체한 것이 아니라 별도 실행했다.
- 보관함 전체 PC/모바일 12개(접힘/목록 무변경, 이름 중복, 저장·새로고침·확인/취소·불러오기·삭제, 5개 제한, 390px·44px, 지연 읽기, 두 탭 동시성) 통과.
- Codex 전체 웹 272개·타입·Pages 4개 통과. 첫 lint에서 확인창의 noninteractive 키보드 이벤트 오류를 발견해 Claude에 수정시켰다. 규칙 억제 없이 pending 확인창 내부의 Escape만 처리하는 문서 리스너로 변경했고, Codex lint/타입 및 PC·모바일 취소·focus 복귀·불러오기·삭제 2개 재검사 통과.
- quota/blocked/timeout/손상 본문은 Node 대역 검사로 확인했다. 실제 저장공간을 소진하거나 실제 친구 방 연결을 이번 브라우저 배치에서 실행한 것으로 표시하지 않는다. 방 전환 gate는 단위 검사 및 코드 검토 범위다.
- 단순한 저장 기능 검사이며 실제 사용자 효용·승패 예측 검증이 아니다. main 머지·배포 없음.
