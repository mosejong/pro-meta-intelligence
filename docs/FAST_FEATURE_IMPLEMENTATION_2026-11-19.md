# 빠른 구현 묶음 · 가정 여러 시드 비교 / PNG 저장

2026-11-19 사용자 지시에 따라 구현 후 변경 부분의 짧은 핵심 확인만 했다. 기존 전체 웹341/Pages5/브라우저6 수치는 이 두 기능 추가 전 기록이다. 새 기능을 포함한 전체 회귀·실제 폰 조작은 다음 통합 배치로 남긴다.

## 구현

- 가정 A/B를 같은 사전 지정 시드 목록1~30으로 명시 실행한다. 기본20쌍/최대30쌍이며 팀 ID를 기준으로 대응한다. 모델 내부 승리 횟수와 B-A 자원/킬/종료분의 최소·중앙·최대를 표시한다. 실제 승률이나 표본 신뢰구간이 아니고 선수·챔피언의 실제 효과도 아직 없다. 현재 실행과 기준이 바뀌면 이전 결과를 표시하고 자동 재계산하지 않는다.
- 완료 밴픽에서 PNG 다운로드를 요청한다. 외부 이미지/네트워크 없이 텍스트로 양 팀5픽·5밴·패치·자료 기준일을 그린다. 길거나 빈 이름 처리, 중복 클릭 방지, 원본 불변, 실패 안내, 객체URL 정리를 연결했다. 다운로드 요청이 기기에 실제 저장 완료됐음을 보증하지 않는다.

## 짧은 확인과 수정

- 새 핵심 검사11개·타입 검사 통과. 변경 파일 대상 lint에서 React ref render 쓰기 오류를 발견해 effect로 옮겼다. 이후 해당 컴포넌트 대상 lint 결과를 별도 로그로 남겼다. 전체 npm/Pages/브라우저는 추가 실행하지 않았다.
- 첫 PNG 검사에서 소스 정규식에 들어간 실제 U+2028/U+2029가 문법 오류를 일으켰다. Claude가 code-point 검사로 수정했고 핵심 검사가 통과했다. 같은 오류를 환경 문제로 처리하지 않았다.
- 서로 다른 가정의 관측 결과가 우연히 모두0이어도 '같은 가정'으로 말하지 않도록 문구를 구분했다. 저장 버튼의 과거 결과 안내도 '저장 완료' 대신 '다운로드 요청'으로 수정했다.

실제 iOS/Android 다운로드와 새 batch 버튼 조작은 미검증이다. 캔버스 단위 대역 검사를 실기기 PNG 저장 확인으로 쓰지 않는다. 새 unit은 일반 테스트 명령에 등록했지만 전체 테스트는 다음 통합에서 실행한다. 제품은 로컬만, 푸시·배포 없음.
