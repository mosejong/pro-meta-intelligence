# 사람 평가 전 멀티에이전트 예비 점검

## 목적과 범위

사용자 요청으로 분석 에이전트 4개, 별도 채점 에이전트 2개와 제품 검토 에이전트
1개를 사용한다. 클로드는 별도로 평가 절차를 감사할 예정이다. 이 기록은 사람
평가와 별개다. 같은 계열 모델의 공통 편향과 문체를 통한 조건 추정 가능성이 있다.
에이전트의 작업 시간은 사람의 판단 시간으로 환산하지 않는다.

이번 점검은 35사례 사람 평가의 축소판을 그대로 대체하지 않는다. 7팀에서 하나씩
골라 KC SUPPORT, BLG MID, GEN JUNGLE, DK TOP, TES BOTTOM, IG SUPPORT,
LYON MID를 비교한다. 교대로 최고 순위 후보를 사용 불가로 만들어 조건 준수를
확인하고, 우리 선수 준비 상태는 UNKNOWN, 현재 차례는 우리 BAN으로 고정한다.
이는 실제 경기의 완성된 밴픽 상황이 아닌 가상 검토 사례다.

## 자료 분리와 재현

```powershell
python ops/agent_utility_dry_run.py --output outputs/NEW_RUN
python ops/agent_utility_dry_run.py --mode collect --output outputs/NEW_RUN
python ops/agent_utility_dry_run.py --mode report --output outputs/NEW_RUN
```

첫 명령은 매번 새 디렉터리에만 실행한다. 실행에 새 원본 수집은 필요 없다.
7팀의 현재 스카우팅 자료에서 양 조건에 동일한 포지션별 최근·시즌 기록과
국제대회 포지션 메타를 준다. 시즌 챔피언별 경기 수는 모두 유지하되 예시 경기
참조는 최대 2개다. 사용 조건에는 파생 예상 픽과 주력 제거 요약을 더한다.
네 참가자가 각각 7개를 답하며, 각 사례는 사용 2·미사용 2개다.

참가자에게는 자신의 `analyst-N-input.json`만 읽도록 지시했다. 다른 에이전트와
파일시스템을 공유하므로 이것은 접근 권한으로 강제된 격리가 아니다. 인간 평가
시에는 진행자가 실제로 자료를 분리해서 전달해야 한다.

응답 파일은 `analyst-N-responses.json`으로 저장한다. 수집기는 고정 자료 해시와
참가자 자료 일치, 응답 중복·누락, 다른 사례 인용, 실제 존재하는 자료 경로를
검사한다. 자료 경로의 존재가 내용의 사실성을 보장하지는 않는다.

채점자는 `blind-packet.json`만 받고 응답당 세 항목 0~4점과 중대한 오류 여부,
근거를 기록한다. 인용 자료가 파생 요약인지 문체로 드러날 수 있으므로 완전한
맹검이라고 부르지 않는다. 각 채점자의 별도 파일이 모두 있어야 집계한다.
배정표와 시간, 참가자 이름은 채점 파일에 포함하지 않는다.

## 결과 해석

원본 답변·자료·채점은 `outputs/agent-utility-20261111/`에 비공개로 남긴다.
보고서는 조건별 평균과 사례별 차이, 중대한 오류에 대한 채점자 불일치를 표시한다.
통계적 유의성이나 인과 효과는 계산하지 않는다. 사람이 관여하지 않은 이번
점검에서 `human_utility_proven`은 항상 false다. 기존 사람 평가 보고서는 갱신하지 않는다.

제품 검토에서는 이미 고른 챔피언의 포지션 준비 상태를 확정할 수 없다는 점과,
화면의 제한된 선수 풀 밖에 있는 관측 조합에 준비 확인을 입력할 수 없는 문제를
발견했다. 해당 수정은 별도 회귀 테스트로 확인한다. 정적 자료에 대한 에이전트
점수가 웹 화면의 안전성을 대신 검증하는 것은 아니다.
