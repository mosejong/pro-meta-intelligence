# 사이드탭 통합 검토

사용자 요청: 한 페이지에 너무 많은 정보를 쌓지 않고 사이드탭을 활용한다.
Claude Opus 5.5 Medium 구현, Codex 구조·시각·반례 및 최종 검사 담당. 배포 승인이 아니다.

## 최종 구조

- 팀 선택은 공통 영역에 한 번만 표시한다.
- 모의 밴픽 / 선수·로스터 / 상세 분석 / A/B 비교 / 시뮬레이션 준비로 나누고 선택한 패널만 표시한다.
- 1100px 이상은 왼쪽 144px 레일, 좁은 화면은 고정 가로 스크롤 탭이다.
- 모든 패널을 마운트한 채 hidden 처리하여 선수·드래프트·기준 A·역할·고정 입력을 보존한다.
- 전체 챔피언 정보는 상세 분석으로 옮겼다. 확정 슬롯 클릭은 상세 조회만 하며 새 픽·밴으로 처리하지 않는다.

## 부모가 추가 검토한 부분

- PC에서 마지막 탭을 선택하고 포커스를 탭 밖으로 옮긴 다음 390px로 줄이는 반례를 추가했다. 첫 빌드에서 선택 탭이 가려져 실패했다. Claude가 스크롤 효과에 railVertical 의존성을 추가했고 Codex는 locale 의존성도 추가했다. 최종 E2E로 재검사한다.
- 별도 탭에 들어간 뒤 다시 펼침을 누르게 하지 않도록 RosterWorkshop/SimulationReadinessPanel에 defaultOpen 옵션을 추가했다. 독립 컴포넌트의 기존 기본값은 접힘으로 유지하고 작업실에서는 펼침으로 시작한다.
- 기존 연간 기록 E2E 두 진입점은 펼쳐진 로스터를 다시 눌러 닫는 옛 흐름이었다. 열려 있지 않을 때만 펼치도록 고쳤다. 최초 전체 실행의 실패를 숨기지 않고 해당 파일을 수정본으로 재검사한다.
- 시뮬레이션 준비의 '기본 접힘' 기대도 전용 탭에서 바로 펼쳐지는 요구로 갱신했다. 미완료 입력의 확정 비활성·밴픽 조작 보존 검사는 유지했다.
- 확정 슬롯에서 상세 정보로 이동할 때 숨겨진 원래 슬롯에 초점이 남지 않도록 상세 정보 영역에 초점을 함께 옮겼다. PC·모바일 모두 초점과 드래프트 불변을 확인했다.
- 모든 탭의 숨김 여부와 캡처를 확인했다. roster tab에서 명단이 즉시 보이는 것을 시각적으로 확인했다.

## 화면 밀도 실측

새 기기 상태, 같은 로컬 자료, Chrome에서 진입 직후(패널을 추가로 펼치지 않음)의 문서 높이:

| 화면 | 개편 전 | 개편 후 | 감소 |
|---|---:|---:|---:|
| 1440×1000 PC | 1657px | 1150px | 507px |
| 390×844 모바일 폭 | 2636px | 1924px | 712px |

범용 성능 수치나 실제 휴대폰 측정은 아니다. 탭 변경으로 마운트 비용이 줄었다고 주장하지 않는다.
전후 측정/캡처: `outputs/studio-sidetabs-20261118/{before,after}.json`, `desktop-before.png`, `desktop-after.png`, `mobile-before.png`, `mobile-after.png`.
다른 패널은 `desktop-roster.png`, `desktop-analysis.png`, `desktop-comparison.png`, `desktop-simulation.png` 및 모바일 대응 파일이다.

## 검사

- 빌드 포함 웹 전체 165/165 통과.
- typecheck/lint 및 Pages 4/4 통과.
- 실제 Chrome 전체 UI 회귀 78항목: 75통과, 옛 기본 접힘 기대 2건 실패, PC→모바일 전환을 PC 프로젝트에서만 실행하여 1건 의도적 skip. 두 기대를 새 요구로 수정한 뒤 PC·모바일 재검사 2건 모두 통과했다. 마지막 초점 이동까지 포함한 표적 검사 총4/4 통과. 모든 검사가 최초 전체 실행에서 한 번에 통과했다고 주장하지 않는다.
- 최초 player-season 진입점 실패는 수정본 새 프로세스 단독 검사 통과 후 위 전체 실행에서 PC·모바일 모두 통과했다. 당시 읽어 둔 옛 검사를 계속 쓰던 실행은 해당 exec세션 Ctrl-C로 중단했다. PID만으로 임의 Node 작업자를 중단하는 요청은 자동검토가 거절했고 실행하지 않았다.
- 최종 source는 빌드 포함 웹165/165, 타입·린트, Pages4/4를 재검증했다. 변경 뒤의 표적 검사4/4도 통과했다.
- 결과 로그 `outputs/studio-sidetabs-{web-final,typecheck-final,lint-final,pages-final,targeted-final}-20261118.log`. 전체 UI 원본 보고서와 표적 보고서는 `outputs/studio-sidetabs-20261118/{full-ui-results,targeted-ui-results}.json`.

실제 기기·다른 브라우저·전체 앱 접근성 인증은 이번 검사 범위 밖이다. 모델·자료·저장 파일 스키마·추천 점수는 바꾸지 않았다.
