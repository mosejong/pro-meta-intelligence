# 고정 밴픽 가정 실험·재생 · 독립 검토

Claude Opus 5.5 medium 구현, Codex 독립 검토. 로컬 기능이며 공개 배포하지 않았다.

## 구현 범위

- 기존 입력 준비에서 검증된 밴픽 20개·선수 10명·역할 10개의 snapshot을 실행 맥락으로 고정한다. 사용자 라인/운영/한타 가정과 재현 번호로 기존 assumption-manager-v1 엔진을 명시적으로 한 번 실행한다.
- 엔진에 선수·챔피언·역할·시즌·룬/아이템의 실제 효과를 넣지 않는다. 고정한 팀·밴픽 맥락을 보여주지만 **실제 LoL 승패·승률 예측이나 실제 경기 재현이 아니다**. 초기 가정 0도 모델 입력의 시작값이다.
- 재생/일시정지/처음/한 단계/1x·2x·4x/시점 이동을 지원한다. 조작은 이미 계산한 사건의 표시만 바꾸며 재계산하지 않는다. 시점 이전 사건으로 상태를 만들고 종료 이전에는 모델 결과를 숨긴다.
- 현재 밴픽·로스터·가정값이 바뀌어도 기존 실행은 고정 보존하고 차이를 표시한다. 실행 기록은 메모리 전용이며 새 저장/공유 형식은 만들지 않았다. 모델/추천 규칙/준비 검증/기존 저장 형식은 변경하지 않았다.

## 독립 검토 및 수정

- 40개 실행의 전 시점에서 최종 상태 일치, 자원·기지 변화, 종료 전 결과 비노출, 되감기 상태를 대조했다. 미래 결과/상태를 바꿔도 이전 시점 표시가 변하지 않는 회귀 검사도 통과했다.
- 상속된 팀 행/가정값이 명시 입력처럼 수용되는 반례를 재현해 Claude가 own-property 검사로 수정했다.
- 내부 파서는 0.25를 받는데 HTML number input의 step=0.1이 기본 form 제출을 막는 문제를 실제 Chrome에서 재현했다. Claude가 native 제약과 파서 계약을 맞추고 실제 0.25 입력·Enter 실행 회귀를 추가했다. 재현 번호의 의미도 쉬운 문구로 보완했다.
- 최종 Codex 독립 **웹 309개**, 타입·lint·Pages **4개**, PC/모바일 새 브라우저 **4개** 통과. 각 환경에서 준비 전 차단 및 준비→소수값 실행→pause/step/배속/seek/reset→자동 종료→현재 로스터 변경 후 기존 실행 보존을 확인했다. 가로 넘침·키보드·클라이언트 오류도 검사했다.
- 기존 자동 밴픽 **1,680회/84경기**의 결과가 그대로였다. 자료 정합성 점검은 SEASON_COMPATIBLE(패치16.20, cutoff 11/18 01:35 UTC)이었다. 검사 수를 실전 효용·추천 품질·사용자 재미의 입증으로 사용하지 않는다.
- Python 제품 코드는 이 단계에서 바꾸지 않아 전체 Python을 재실행하지 않았다. 이전 운영 수정의 546개 수치를 이번 UI 변경 뒤 검사로 합치지 않는다.

## 한계와 후속

재생 상태는 기존 모델의 보너스 상수를 재사용해 복원하며 실행 때 최종 상태를 모델 결과와 대조해 차이가 있으면 표시를 거부한다. 실제 아이템 패시브/선수 실력/시대 보정이 없는 가정 엔진이다. 고정 맥락에는 선수 snapshot도 있지만 상세 표시를 전체 원본 기록 뷰로 확장한 것은 아니다. 사람의 재미·이해도·실전 정확도는 미검증이다.
