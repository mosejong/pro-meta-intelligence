# 2단계: 밴 후보 개선안 (실행 전 고정) · 2026-11-23

[평가 기준](DRAFT_RULE_WALK_FORWARD_PROTOCOL_2026-11-23.md)과 [첫 측정](DRAFT_RULE_WALK_FORWARD_RESULT_2026-11-23.md)에 이어, 밴 후보만 바꾸는 개선안 두 개를 **실행 전에** 고정한다. 픽은 바꾸지 않는다.

| 이름 | 밴 점수 (높은 순, 같으면 챔피언 이름 순) |
|---|---|
| `PATCH_PRESENCE` | 같은 패치의 (픽 + 밴) ÷ 같은 패치 경기 수 |
| `PATCH_PRESENCE_WITH_OPPONENT` | 위 값 + 상대 팀 공개 우선 픽의 게임 비율 |

- 입력: 보고서의 `patch_presence`(보고서 기준 시각에 알려진 같은 패치 경기만). 서비스 피드와 평가 자료가 같은 함수로 만든다. 값이 없으면 현재 규칙으로 돌아간다.
- 가중치나 상위 몇 개 같은 조정값은 없다. 결과를 보고 수정하지 않는다.
- **선택 순서:** DEV top-3가 더 높은 쪽 하나를 후보로 정한다. 그 후보만 [채택 규칙](DRAFT_RULE_WALK_FORWARD_PROTOCOL_2026-11-23.md#개선안-채택-규칙-23단계에-적용) 1~4를 VALIDATION에서 확인한다. 다른 하나의 VALIDATION 결과도 함께 기록한다.
- 통과하면 서비스 기본값으로 바꾸는 별도 PR에서 설명 문구·근거 표시를 함께 정리하고, HOLDOUT은 개선이 모두 끝난 최종안으로 한 번 연다.
