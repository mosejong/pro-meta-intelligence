# 밴픽 기기 저장 대기 제한

2026-11-17. `draft-session.ts`의 IndexedDB 열기/읽기/쓰기 경로에 각 10초 제한을 추가했다.
원래는 콜백이 오지 않으면 복원 확인·쓰기가 끝나지 않아 시작 화면 또는 저장 큐가 무기한 대기할 수 있었다.

- blocked 연결은 즉시 실패. 종료 후 뒤늦게 열린 데이터베이스는 닫는다.
- 읽기/쓰기 시간초과 시 해당 트랜잭션을 abort하고 DB를 닫는다.
- 실패 뒤 쓰기 큐는 다음 저장을 계속 처리한다. UI의 기존 실패 경고·최신값 수동 재시도 흐름은 유지한다.
- v2/v3 밴픽 파일 형식과 성공 저장의 의미는 바꾸지 않는다. 초과가 저장 성공을 뜻하지 않는다.
- 단계별 10초이므로 DB 열기+읽기는 최악 20초까지 걸릴 수 있다. 실측 성능 목표가 아닌 무한 대기 방지다.

단위: 기존 autosave 4개+새 대기 검사 3개 = 7/7 통과.
전체 웹 빌드·143검사, 타입·린트·Pages 4개도 통과했다.
새 Chrome 시나리오는 DB open 무응답→밴픽 사용 가능→저장 실패→DB 복구→최신 밴픽 재저장을 검사한다. PC·모바일 폭에서 통과했다. 로스터/기존 밴픽 포함 24/24 E2E 및 입력 준비와 함께 재검사한 8/8 E2E도 통과했다.

이 코드는 기존 복원 E2E 1회 간헐 실패의 원인을 규명한 것은 아니다. 다른 장애(콜백 무응답)를 별도로 차단한다.
