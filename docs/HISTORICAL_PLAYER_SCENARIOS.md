# 다년간 선수 기록과 시대를 넘는 가상 조합

2026-11-18 · 사용자 범위 확정: 2014년부터 현재까지. 올해 활동선수뿐 아니라 복귀 선수와 과거 시즌 선수를 다룬다.

## 사용 흐름

기본은 팀 선택 → 밴픽 → 조합 비교 → 링크 공유다. 연도 선택은 선수 카드/로스터의 상세 선택으로 둔다. JSON은 기본 이용 절차가 아니다.

- 현재 관측 선수: 현재 스냅샷 선수와 올해 근거를 보여 준다.
- 과거 시즌 선수: 예를 들어 `2015 MaRin`, `2020 Nuguri`, `2022 Nuguri`처럼 선수+시즌을 선택 단위로 삼는다. 해당 시즌 자료를 확보·검증한 경우에만 관측 챔피언 횟수를 표시한다.
- 시대 교차 시나리오: 과거 시즌 선수를 현재 조합에 넣는 것은 사용자 가정이다. 현재 패치에서의 실력, 시너지, 적응 속도, 승률은 과거 기록만으로 계산하지 않는다. 실제 기록과 가상 가정은 화면과 저장 형식에서 구분한다.
- 복귀 선수: 보도/에이전시 계약/팀 입단/실제 출전은 별개의 사실이다. 과거 경기만 있다고 현재 팀 명단에 자동 편입하거나 은퇴·비활동·복귀를 추론하지 않는다.

## 공개 안내 한 줄

> 2014년 이후 자료를 순차 확보 중이며, 연도·대회별 수집 범위와 누락이 있을 수 있습니다.

기존 연간 기록 섹션에는 현재 2026년만 표시한다는 문구를 함께 넣는다. 2014~2026 파일이 목록에 등록됐다는 것과 모두 내려받아 검증했다는 것을 혼동하지 않는다.

## 이번에 실제로 확보한 자료

- 공식 OE 공개 폴더의 2014~2026 각각의 파일명·파일 ID를 브라우저에서 직접 확인했다. 일반적인 폴더 크롤러·임의 ID 검색·새 호스트를 허용하지 않는다.
- 2022년 파일을 기존 정책 게이트/정확한 파일 ID/24시간 전역 간격으로 한 번 받았다. 파일크기 97,571,301 bytes.
- SHA256 `76b7cb8afc1c65c7e220053b1c5296c593e00c3a6dfaee4ef47373aa64b42a0a`, 실제 취득 `2026-11-18T00:45:22.279927Z`.
- 이전에 확보한 2026년 원본도 유지한다. 나머지 11개 연도는 아직 미수집이다. 다음 우선순위는 2015 → 2020 → 2021 → 나머지 최신연도 역순이다.
- 오늘 다운로드 이후 다음 시도는 **11/19 09:45:22 KST 이후**다. 실패도 하루 간격을 소모한다. 2026년 자동 갱신과 동일한 제공자 예산을 사용하므로 동시에 매일 각각 요청할 수 없다.
- 새 예약 작업은 설치하지 않았다. 순차 실행 명령은 아래와 같고, 아직 실행 시간이 아니면 네트워크 없이 대기 시각을 출력한다.

```powershell
python -m ops.player_career_archive
python -m ops.player_career_archive --fetch-next --output outputs/history-next-attempt.json
```

실패/정책 만료/자료 무결성 문제를 우회하지 않으며 기존 파일을 임의 덮어쓰지 않는다. 원본 CSV를 웹이나 git으로 재배포하지 않는다.

## 커리어 집계 경계

새 `player-career-history`는 기존 `player-season-history`를 대체하지 않는다. 기존 가상 로스터·역할·A/B 파일 형식도 유지한다.

- 출처 ID+선수 ID를 정확히 매칭하며, 같은 이름을 합치지 않는다. 팀/역할/시즌/패치 구간은 남긴다. 팀을 옮긴 동일 선수의 커리어는 출처 ID가 같은 경우만 나란히 보여 준다.
- CSV의 year가 시즌이다. 경기 발생 달력연도와 다를 수 있다.
- 오래된 파일에 firstPick/밴 순서가 없어도 선수의 챔피언 사용 기록만 집계할 수 있다. 12개 참가자, 양쪽5역할, 선수·팀ID, 서로 다른 챔피언, 일치하는 결과/시각을 검증한다. 픽 순서나 없는 밴픽 이벤트를 만들어 내지 않는다.
- 원본 해시와 실제 취득시각을 유지한다. 지금 받은2022원본을2022년에 확보했던 것으로 바꾸지 않는다. 따라서 과거시점 예측 검증에 그대로 사용하지 않는다.
- 같은 논리 경기의 중복 스냅샷은 한 번 세고 충돌하면 양쪽을 제외한다. 전체 원시게임은 계속 보관하지 않고 검증용 해시와 요청한 선수의 사용 행만 집계한다.
- NOT_LOADED(파일 미확보), NOT_OBSERVED(확보·채택 범위에서 미관측), OBSERVED(관측)를 구분한다. 빈 기록은 낮은 실력이나 챔피언 숙련도0이 아니다.
- 관측 공백은 마지막 확보된 경기부터의 경과일이다. 누락된 시즌을 실제 미활동으로 간주하지 않는다.
- 원본의 팀 이름은 제공자가 나중에 수정한 명칭일 수 있다. 2022파일의 Dplus Kia 표기를 당시 공식 브랜드를 입증하는 자료로 쓰지 않는다.

## 다음 연결

1. 필요한 연도별 자료를 순차 확보하고 선수 ID/경기 수/누락을 검증한다.
2. 선수+시즌 선택과 관측 챔피언 카드 조회를 기존 로스터와 별도 버전으로 연결한다. 현재 명단을 자동 변경하지 않는다.
3. 과거 시즌 조합 재현과 현재 패치에 놓는 가상 조합을 구분한다. 현재 패치에 없던 챔피언/아이템/룬은 자동 변환하지 않는다.
4. 시대 보정·선수 효과는 별도 실험으로 검증된 경우만 추가한다. 이번 픽 검증에서 단순 시즌 혼합의 우위는 없었다.
5. 친구 링크는 우선 팀·밴픽만 전달한다. 선수·시즌 선택이 연결되기 전에는 카드와 역할이 공유된다고 표시하지 않는다.

## 검증과 남은 경계

- Python 전체379/379, ruff 검사·포맷 통과. 처음 새 전체검사에는 기존 피드 테스트의 Windows 파일 교체 접근 오류1건(378통과)이 있었으며, 새 테스트 폴더에서 재검사379통과했다. 로그를 보존하고 보관소 안전장치를 완화하지 않았다.
- 에이전트20개 반례 이후 부모가 짧은 CSV행·2014이후 전체범위·잘못된출처타입·전역다운로드실패시도·연도별캐시·순차계획·스냅샷충돌·과거메타데이터·옛스키마 반례를 보완했다.
- 교차 검토가 지적한 옛 CSV 다운로드 스키마, 최신스냅샷만 선택하던 충돌 누락, 과거 계획에 미래취득 메타데이터가 섞이는 문제를 수정했다. 현재 시즌의 엄격한 드래프트 수입 계약은 유지한다.
- 순차 수집 명령을 구현했지만 새 예약 작업이나 동시 수집 조정기는 설치하지 않았다. 운영 작업에 연결할 때 현재 시즌 수집과 직렬화해 제공자 예산을 공유해야 한다.
- 과거 선수·시즌 선택 UI와 시대를 넘는 경기력 보정/승패 모델은 아직 연결하지 않았다. 새 파일이 확보될 때마다 실제 선수ID와 채택/제외 범위를 검증해야 한다.
