# API·데이터 제공 범위 조사

확인일 2026-11-17 · 외부 문서·공개 정적 JSON의 접근 확인과 로컬 코드 점검을 수행했다.
새 계정·키 발급·OE 수집·제품 수집 설정 변경은 하지 않았다.

## 1. 결론

| 필요한 자료 | 우선 경로 | 현재 판정 |
|---|---|---|
| 프로 선수/팀의 시즌·최근 밴픽 | 기존 OE 집계 | 현재 연결됨, 전체 구매 기록은 없음 |
| 챔피언·아이템·룬 설명/이미지 | Riot Data Dragon | 정적 자료 제공; 저장소는 챔피언/버전 작업만 허용 |
| 동의 계정의 경기·챔피언 성향 | Riot Web API | API 계열 존재, 저장소 비활성·운영 키/서버 필요 |
| 구매 순서·시간별 성장 | 개인 Match-V5 timeline / 프로 GRID 후보 | 출처별 계약과 실제 응답 검증 필요 |
| 프로 경기 상세 사건 | Riot Games Open Access powered by GRID | 무료 실험 경로 확인; 상업용 별도 라이선스 |
| 이적·로스터 확정 | 팀/리그 발표와 명시적 검토 | 경기 CSV만으로 현재 소속 확정 불가 |
| 인터뷰/발언 | 원본 영상·공식 인터뷰 | 원문·시각·번역 확인 필요; 개인 평가와 데이터 사실 구분 |
| OP.GG 표시 자료 | 공식 안내 범위 안의 별도 검토 | 일반적인 제3자 데이터 API 제공이라고 간주하지 않음 |

**API가 있다는 것, 우리 계정이 접근 가능한 것, 상업적으로 재사용 가능한 것은 별개다.**

## 2. 로컬에서 직접 확인한 사실

`src/pro_meta_intelligence/config/source_registry.json` 기준:

| source_id | 상태 | 허용 작업 |
|---|---|---|
| oracles-elixir-match-data | ENABLED | FETCH_PUBLISHED_CSV, IMPORT_LOCAL_CSV |
| riot-data-dragon | ENABLED | FETCH_VERSION_INDEX, FETCH_CHAMPION_CATALOG |
| riot-web-api | REVIEW_REQUIRED | 없음 |
| lol-esports-schedule | ENABLED | FETCH_SCHEDULE_HTML |

내부 ENABLED는 Riot의 제품 승인이나 새 작업 허용이 아니다. 신규 작업은 도메인,
인증, 상업/재배포 조건, 보관, 쿼터, 파서·실패 처리를 등록한 뒤 좁게 활성화한다.
OE는 현재 하루 한 번·검토된 정확한 파일 ID만 사용하고 원본을 공개하지 않는다.

로컬 11/11 CSV `fcd2e451…6944de.csv`의 헤더 165개를 직접 확인했다.
item 관련 열은 없고 일부 시점별 골드 열은 있다. 골드만으로 구매 내역을 복원할 수 없다.
현재 웹 7팩은 11/14 00:19:10 UTC 기준이며 결승 전 자료다.
source_version은 `sha256:80dbfab85edd2ed97672cf7ecb4fefe3eac375adc116249a0f1a4a0cf6dabbd2`.
결승 결과 표시를 바꿔도 이 팩이 결승 포함 자료로 바뀌는 것은 아니다.

## 3. 일반 계정: Riot Web API

공식 문서에서 Riot ID→PUUID와 플랫폼/지역 라우팅, RSO의 운영 키 요구를 확인했다.
RSO는 본인 계정 연결 수단이며 단순 Riot ID 입력만으로 소유가 증명되지는 않는다.
현재 랭크를 과거 경기 당시 랭크로 소급할 수 없다.
출처: [LoL 개발 문서](https://developer.riotgames.com/docs/lol).

| 계열 | 사용 목적 | 경계와 구현 전 확인 |
|---|---|---|
| ACCOUNT-V1 | Riot ID와 PUUID 연결 | 지역·출처별 ID 계약; 개명·이전 대응 |
| SUMMONER-V4 | 계정 프로필 | 프로 선수 OE ID와 자동 결합하지 않음 |
| MATCH-V5 | 경기 목록·상세·타임라인 | 실제 DTO/보관 범위/큐별 누락 계약 검사 |
| LEAGUE-V4 | 조회 당시 공식 랭크 | 큐·조회 시각 기록, 과거 랭크 추정 금지 |
| CHAMPION-MASTERY-V4 | 챔피언 숙련도 시스템의 기록 | 포인트를 승리 기여도·실력으로 치환하지 않음 |
| RSO 계열 | 승인된 본인 계정 연결 | 운영 키·앱 승인·서버 인증 설계 필요 |

공식 [API 목록](https://developer.riotgames.com/apis)에서 계열은 확인했다.
이번 브라우징에서는 동적 Reference의 최신 전체 DTO가 노출되지 않아, 모든 필드와
정확한 현행 경로를 인증 요청으로 확인한 것은 아니다. 오래된 by-name/by-summoner 예제를
복사하지 말고 구현 시 현재 Reference와 권한 있는 샘플로 계약 테스트한다.

### 아이템·룬에서 기대할 자료와 아직 검증할 것

최종 장비와 perks가 포함된 Match-V5 과거 예시는
[RiotTuxedo 공개 예시](https://gist.github.com/RiotTuxedo/c8e2d29d12fc1e405ade267def036362)에 있다.
이는 2021년 예시이며 현재 모든 응답의 보장이 아니다. 최신 필드, 빈 값,
게임 모드별 차이와 변경 사항을 실제 샘플로 검증해야 한다.

공식 개발자 이슈 저장소에는 2026년 티어 3 신발의 ITEM_UNDO ID가 0으로 나오는
[사용자 제보 #1174](https://github.com/RiotGames/developer-relations/issues/1174)가 있다.
전 API에 동일 버그가 존재한다고 확정할 수는 없지만, 구매·파괴·되돌리기 기록의
해석 불능을 정상 상태로 처리하는 회귀 사례가 필요하다. 추측 구매를 관측 사실로 저장하지 않는다.

### 인증·쿼터·공개 서비스

개발 키는 24시간마다 만료하고, 개인 키는 공개 알파/베타에도 사용할 수 없다고
안내한다. 공개 API 제품에는 운영 키를 신청한다. 문서상 개인 키 기본 쿼터는
초당 20회/2분당 100회, 운영 키 시작 한도는 10초당 500회/10분당 30,000회지만
실제 앱·메서드·서비스 한도와 응답 헤더가 우선이다. 429는 Retry-After를 따른다.
출처: [개발 포털 안내](https://developer.riotgames.com/docs/portal).

요청량은 '계정 조회 + 목록 페이지 + 신규 상세 N + 필요한 타임라인 M + 보조 조회'로
산정한다. 매 페이지 로드마다 같은 경기를 다시 받지 않는다. 큐·패치·시간 범위를
제한하고, 중복 제거·캐시·취소·제한 응답을 처리한다. 개발 키 자동 갱신으로 공개
서비스를 운영하거나 여러 키로 쿼터를 회피하는 설계는 사용하지 않는다.

## 4. 프로 경기: 새 GRID Open Access

라이엇의 11/12 발표는 11/14부터 커뮤니티 접근을 열고 Worlds 2026을 첫 대회로
제공한다고 안내한다. Central Data Feed, Series State API, Loopfeed와 라이브
5분 지연을 언급한다. 사이트별 출시일 표현에는 차이가 있어 실제 접근은 포털에서
확인한다. 출처: [LoL Esports 공식 발표](https://lolesports.com/en-US/news/build-with-official-league-of-legends-esports-data).

GRID는 무료 Open Access를 비상업 학습·실험 용도로 설명하고, 상업 제품은 별도
맞춤 가격 라이선스를 요구한다. 무료 연구 자료를 광고 서비스로 그대로 옮기지 않는다.
출처: [GRID Open Access 안내](https://grid.gg/riot-open-access/).

| 이번에 확인 | 키 발급·권한 확인 뒤 검증 |
|---|---|
| 공식 제공 경로와 API 제품 이름 | 계정에 열린 정확한 대회·과거 시즌 범위 |
| 무료 비상업/상업 라이선스 구분 | 구매/판매/되돌리기·룬·좌표 필드와 샘플 |
| 라이브 지연 안내 | 모든 세트 수록 여부, 이벤트 누락·정정 방식 |
| 계정·API 키 필요 | 쿼터, 보관·모델 학습·파생 결과 공개/재배포 권한 |

[공개 docs](https://docs.grid.gg/public/documentation)는 이번 도구에서 본문을 읽을 수
없었다. 구매 타임라인이 특정 무료 키에 제공된다고 확정하지 않는다.
일반 계정 Match-V5 키로 이 프로 경기 자료를 조회할 수 있다고 가정하지 않는다.

## 5. 정적 자료와 로컬 클라이언트

Data Dragon은 챔피언·아이템·룬 등 정적 자료를 제공하지만 추천 빌드나 전투 엔진은
제공하지 않는다. 패치별 버전을 고정하고 클라이언트 패치와의 대응을 확인한다.
현 저장소는 아이템/룬 카탈로그 작업이 아직 허용되지 않았다.
Live Client API는 실행 중인 로컬 게임 자료, Replay API는 리플레이 조작용이다.
웹 방문자 전체나 과거 프로 경기의 범용 원격 엔진으로 보지 않는다.
출처: [정적/클라이언트 공식 문서](https://developer.riotgames.com/docs/lol).

정적 설명만으로 스킬 타격·패시브·아이템 상호작용을 모두 재현할 수 있다는 근거는
없다. 설명 JSON과 계산 룰을 별도 버전으로 관리하고 미지원 조합을 명시한다.
이번 조사에서는 게임 클라이언트 접속·설정 변경·설치를 하지 않았다.

### 공개 정적 JSON 접근 확인

웹 도구로 아래 주소를 읽지 못해, 공개 URL을 일반 HTTP 요청으로 확인했다.
원본을 파일로 저장하거나 저장소의 수집 허용 목록을 변경하지 않았다.

| 연구용 확인 URL | 응답 | 확인한 최상위 구조 |
|---|---|---|
| [16.20.1 한국어 item.json](https://ddragon.leagueoflegends.com/cdn/16.20.1/data/ko_KR/item.json) | HTTP 200 | dict, type/version/basic/data/groups; data 항목 870개 |
| [16.20.1 한국어 runesReforged.json](https://ddragon.leagueoflegends.com/cdn/16.20.1/data/ko_KR/runesReforged.json) | HTTP 200 | list, 최상위 룬 트리 5개 |

870개가 모두 소환사의 협곡에서 구매 가능한 아이템이라는 뜻은 아니다. 맵·모드·
구매 가능 조건·삭제/비활성 여부를 파싱해야 한다. 룬 트리 5개를 룬 5개라고 세지 않는다.
접근 가능 확인은 최신 패치 여부·전체 필드 의미·게임 수치 정확성·전투 계산 가능성을
검증한 것이 아니다. 16.20.1은 이번 확인에 쓴 예시이며 신규 시즌 기본값으로 고정하지 않는다.

## 6. OP.GG와 전적 사이트

OP.GG 공식 도움말은 일반적인 스크래핑을 일괄 금지하지 않으나, 출처 없는 상업 이용이나
과도한 요청은 제한될 수 있다고 안내한다. 수집한 게임 데이터를 일반적으로 제3자에게
제공하는 서비스라고 설명하지는 않는다.
출처: [OP.GG 공식 안내](https://help.op.gg/hc/en-us/articles/31091405109401-Can-I-use-OP-GG-data).

따라서 '무조건 불법' 또는 '공개니까 무제한 무료 API'로 단정하지 않는다.
상업 서비스의 핵심 수집원으로 선택하려면 현재 약관·구체적 접근 방법·필드·호출량·
재배포 조건을 별도 검토한다. 이번에는 스크래퍼를 만들지 않았다.
직접 공식 원천을 연결하면 제공자 가공 점수의 의미와 UI 변경에 덜 의존할 수 있다는
것은 아키텍처 판단이며, 접근 권한이 이미 있다는 뜻은 아니다.

## 7. 연결 우선순위와 필요한 증거

| 우선 | 작업 | 완료에 필요한 증거 |
|---|---|---|
| P0 | 기존 밴픽 UI·가상 로스터 편집 | 새 수집 없이 동작·잠금·초기화 확인 |
| P1 | 정적 아이템/룬 작업 검토 | 정확한 경로/버전·출처·권한·샘플·파서 테스트 |
| P1 | 로컬 선수 카드 가져오기 계약 | 합법적 출처/동의 범위, 샘플 누락·삭제 처리 |
| P2 | 본인 계정 공식 API 연결 | 운영 등록/키·RSO 필요 여부·서버·현행 DTO |
| P2 | GRID 실험 접근 | 본인 가입/키·대회 범위·구매 이벤트 계약 |
| P3 | 상업용 데이터와 광고 | 출처별 상업권·모델 이용권·비용 승인 |

신규 커넥터의 합격 조건은 단순 HTTP 200이 아니다. 출처 라이선스, 올바른 ID·패치·
시점, 샘플 완전성, 재시도 한도, 키 비노출, 삭제·보관·사용 범위까지 확인한다.
계정 키는 문서·브라우저 번들·git·분석 이벤트에 넣지 않는다.

## 8. 조사 한계

키 없이 공식 공개 문서와 로컬 자료 범위만 확인했다. 광고 승인, API 제품 승인,
프로 경기 샘플 다운로드, 특정 개인 전적 열람, 상업 견적 문의를 수행하지 않았다.
공식 문서에도 오래된 예제/상충 표현이 있을 수 있으므로 최신 Reference와 실제
접근 계약으로 재확인한다. 필요한 자료를 모두 모았다는 주장을 하지 않는다.
