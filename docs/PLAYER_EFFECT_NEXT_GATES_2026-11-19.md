# 선수 효과 연결의 다음 관문

2026-11-19 · 설계 제안. 현재 웹 기능이나 학습/출시 완료 명세가 아니다.

## 지금 확보한 것

시즌 카드로 선수·팀 구성을 저장하고 밴픽 당시 챔피언 관측을 확인할 수 있다.
실제 수치의 형식·누락 점검 및 과거 기록 추출기를 만들었으나 선수 실력/실전 승률을
추정하는 모델은 없다. 현재 시뮬레이션은 지원하는 사용자 가정 범위로만 동작한다.

실제 탐색 878경기에서 동일 패치·역할·선수의 최소5경기 및 모든13개 수치가
10명 전원 준비되는 경기는256개뿐이다. 준비되지 않은 나머지를 삭제하고 전체 기준선보다
좋아졌다고 발표하면 선택 편향이 생긴다. 모든 수치를 동시에 요구해야 한다는 결론도 아니다.

## 다음 순서

1. 지원 범위 CLI를 고정해 누구나 같은 원본 해시로 같은 누락·지원 집계를 재현한다.
2. 실제 필요한 feature를 사전에 소수로 정하고, 대상 전체와 지원 하위집합을 구분한다.
   이전878경기 연구는 탐색용이다. 같은 하위집합의 팀 기준선을 다시 계산해야 한다.
3. 수치 단위·역할·패치·대회 차이와 공개 지연 가정을 검증한다. 패치 간 자료를 합칠 경우
   이전 패치 창과 감쇠·대체 규칙을 먼저 고정하고, 결과를 본 뒤 잘 나온 규칙을 최종 검증으로
   부르지 않는다. 누락은 별도 상태이며 평균0/보통 실력으로 대체하지 않는다.
4. 작은 연구용 선수 feature를 기존 팀 기준선과 같은 경기·같은시점에 비교한다.
   전체와 리그별 Brier/logloss, 예측 가능 비율과 결측에 따른 fallback을 함께 보고한다.
   순수 팀 정보보다 좋아도 선수 교체의 인과적 효과를 입증한 것은 아니다.
5. 출시 후보를 정한 뒤 새로운 미관측 기간/독립 자료로 확률 보정·실패·안정성을 확인한다.
   현재 연구와 사람의 재미·실제 코치 효용 평가는 별개다.

## 역대 선수와 현재 선수

2015마린과2026선수는 같은패치 실전 관측 대결이 존재하지 않는다. 시즌별 상대적 지표를
만들더라도 시대별 상대 수준·아이템·리워크·맵 변경을 알아서 보정했다고 주장할 수 없다.
역대 선수 UI는 우선 실제 관측을 보여주며, 향후 동일 환경으로 옮긴 가상 대결은 사용자 가정과
지원 한계를 명시해야 한다. 현재 과거 선수 실행 가드를 숫자 확보만으로 해제하지 않는다.
