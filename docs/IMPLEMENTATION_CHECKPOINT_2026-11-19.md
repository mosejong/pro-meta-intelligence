# 구현 체크포인트 · 2026-11-19

새 제품 기능은 로컬에만 반영했다. GitHub에 통합한 것은 운영 전용 변경이며, 제품 브랜치는 푸시·배포하지 않았다.

## 이용 흐름

- 밴픽과 현재·과거 시즌 선수 구성을 함께 보관하고 다시 열 수 있다. 기존 저장 형식을 유지하며 이름만 변경할 수도 있다.
- 2015년 카드 140개를 추가했다. 기존 2022·2026년 카드 1,184개를 보존해 현재 총 1,324개다.
- 과거 팀의 역할별 최다 출전 구성을 한 번에 적용한다. 동률·미관측 역할·선수 중복이면 임의로 채우지 않는다.
- 선택한 과거 선수의 챔피언 관측에 현재 밴·픽·피어리스 잠금을 표시한다. 현재 메타 추천이나 실력 추정은 아니다.
- 밴픽 결과를 포지션이 담긴 PNG로 저장하고, 피어리스 여러 세트와 가정 비교 결과를 일반 글로 복사할 수 있다. 자동 복사가 거부되면 직접 선택할 글을 제공한다.
- 가정 실험은 실제 선수·챔피언 효과를 계산하지 않는다. 과거 선수를 선택했을 때 이전 입력으로 새 실험이 실행되지 않도록 차단하고 이유를 표시한다.

## 저장과 게시 경계

- 과거 연습은 같은 사이트에 보존한 정확한 카탈로그 ID·기준 시각으로 복원한다.
- 예전 구단은 선택한 카드의 전체 내용이 현재 카드와 같을 때만 실행 중 참조를 맞춘다. 저장 원본은 덮어쓰지 않는다.
- 독립 검토에서 수동 자료 요청이 보관함 복원을 덮어쓰는 경합을 재현했다. 요청 무효화와 최신 컨텍스트 확인으로 수정했고 실제 브라우저에서 수정 전 실패·수정 후 통과를 확인했다.
- 친구 방 파일을 `.site-public`이나 `static-site` 안에 둘 수 없게 했다. 현재 환경의 파일 저장 설정은 비활성이고 실제 비밀 유출을 확인한 것은 아니다.
- 게시 빌드는 매번 새 작업 폴더에 명시적으로 허용한 파일만 복사한다. 이전 작업 폴더의 포장용 압축 파일이나 사용자 파일은 삭제하지 않으며 새 빌드에 섞지 않는다.

## 실제 확인

- 최신 웹 통합 검사: **429/429 통과**.
- TypeScript와 변경 파일 lint 통과.
- Pages 계약 5개 통과. 위 통합 숫자와 별도다.
- 실제 Chrome에서 저장·복원·취소, 이전 자료의 구단 복원, 마린 선택, 팀 구성 적용과 중복 거부, PNG 다운로드, 가정 비교, 세트 글 공유를 각각 확인했다.
- 과거 팀 구성과 구단 복원은 모바일 폭에서도 확인했다. 실제 iOS·Android 장치 검증은 아니다.
- 원격 CI, 로컬 단위 검사, 브라우저 조작, 사람의 실제 효용 평가는 서로 다른 근거다. 테스트 수를 승률·사용자 만족도 입증으로 쓰지 않는다.

## 실제 자료 연구

현재 확보한 2026년 보관본에서 878경기를 평가했다. 팀 ID만 쓰는 Elo는 전체 평균에서는 단순 기준보다 나았지만 LCK와 EWC에서는 Brier 오차가 더 나빴다. 실제 수집 가용성을 재현한 것이 아닌 경기 시각+24시간 공개 지연 가정이다.

이 값을 서비스 승률이나 선수·밴픽 효과로 연결하지 않는다. 원본 해시와 범위, 표본 및 한계는 [기준선 연구](MATCH_BASELINE_RESEARCH_2026-11-19.md)에 기록했다.

## 남은 핵심

1. 과거·현재 선수의 실제 효과를 추정하기 전에 수치 관측의 유효성, 역할·패치·시점 범위와 누락을 검증한다.
2. 선수·챔피언 효과나 실제 승률을 출시하려면 단순 기준선과 리그별 비교, 새로운 독립 검증 구간이 필요하다.
3. 룬·아이템 관측, 솔로랭크, 로그인과 외부 방 운영은 필요한 출처·키·운영 결정이 준비된 뒤 연결한다.
4. 사람 평가와 실기기 검증, 중국어 번역·중국 접속 및 권리·상업 이용 검토는 공개 전 별도 관문이다.

자동 진행은 실제 완료 파일과 작업 소유를 먼저 확인한다. 한도 오류가 나오면 기록된 초기화 시각에 맞춰 재개하며 잔량·초기화 시각을 추측하지 않는다.
