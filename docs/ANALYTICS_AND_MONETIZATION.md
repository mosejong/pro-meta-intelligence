# 공개 웹·이용 계측·광고 운영 설계

설계 v0.1 · 조사일 2026-11-17 · 계정 생성/결제/광고 코드 설치/배포는 아직 수행하지 않았다.
사용자 목표는 간단한 모의 밴픽을 공개하고 실제 이용량을 확인한 뒤 광고로 수익화하는 것이다.

최신 실행 순서: [비공개 출시 기준](PRIVATE_RELEASE_READINESS.md)에 따라 한국어·중국어
간체와 핵심 품질 관문을 먼저 검증한다. 아래 공개 단계는 그 뒤 사용자 판단을 거친다.
국가별 트래픽은 공개 후 집계 방문·밴픽 완료·재방문과 함께 해석하며, 언어 선택을
실제 접속 국가로 간주하지 않는다. 서버·도메인 구매는 실제 이용 현황을 확인한 뒤 검토한다.

## 1. 운영 순서

| 단계 | 공개하는 가치 | 확인하고 넘어갈 기준 |
|---|---|---|
| 공개 준비 | 로그인 없이 양 팀 밴픽, 상세 근거 | 모바일·키보드·하위 경로·초기화·오류 처리 |
| 계측 베타 | 방문과 밴픽 완료 흐름 | 중복/개발 트래픽 제외, 실제 수집 검증, 거부 상태 처리 |
| 반복 이용 검증 | 저장·재시작·로스터 비교 | 시작 대비 완료율, 재시작/재방문, 오류·이탈 이유 |
| 광고 시범 | 본 기능을 유지하는 배너 | 제품/데이터/광고 승인을 확인하고 한 위치부터 적용 |
| 운영 판단 | 실제 수입과 비용 | 순비용·사용성·정책·콘텐츠 품질을 함께 검토 |

단계마다 사용 지표를 확인한다. 방문 숫자를 늘리기 위해 가짜 승률·선수 평가·인터뷰를
만들거나 예측 미입증을 숨기지 않는다. 초기 트래픽이나 수입을 예상 실적처럼 적지 않는다.

## 2. 지표 정의

| 지표 | 정의 | 해석 주의 |
|---|---|---|
| 방문/페이지 조회 | 선택한 제공자의 정의와 기간을 함께 기록 | 여러 페이지 조회가 여러 사람이 아님 |
| 밴픽 시작 | 첫 유효 밴/픽 확정 시 1회 | 화면 노출·팀 선택만으로 시작 수를 늘리지 않음 |
| 밴픽 완료 | 선택 규칙에 맞는 전체 절차 완료 | 자유 조합은 별도 모드로 집계 |
| 완료율 | 같은 기준 집단의 완료 세션/시작 세션 | 기간 경계·새로고침·탭 중복을 명시 |
| 재실행/비교 | 완료 뒤 새 시나리오 또는 A/B 비교 | 단순 버튼 연타를 별도 실험으로 세지 않음 |
| 재방문 | 선택 제공자가 산정한 기간 내 재방문 | 쿠키 없는 계측으로 정확한 개인 리텐션을 보장하지 않음 |
| 오류율 | 실행 실패/실행 시도 | 모델 미지원·자료 부족과 프로그램 장애를 구분 |
| 시뮬레이션 시간·비용 | 실행별 실제 자원 소모와 대기 | 생성 경기 길이와 실제 계산 소요 시간을 구분 |

### 이벤트 계약 제안

| 이벤트 | 발생 조건 | 허용 속성 예시 |
|---|---|---|
| draft_started | 첫 유효 선택 확정 | ruleset, mode, app_version |
| draft_completed | 규칙별 전체 밴픽 검증 통과 | ruleset, mode, elapsed_bucket |
| details_opened | 사용자가 상세 탭 열기 | section, app_version |
| scenario_saved | 로컬 저장 성공 | scenario_kind, storage_kind |
| comparison_started/completed | 검증된 비교 시작/종료 | supported_mode, run_count_bucket |
| simulation_failed | 실행 실패 | allowlisted_error_code, model_version |

빈도 제한과 세션 내 중복 방지를 둔다. 임의 자유 문자열·원본 오류 메시지·개인
프로필·검색어·계정 ID를 전달하지 않는다. 로컬 모드의 식별자는 브라우저 내에서만
사용하고 외부로 보내야 하는지 별도 결정한다. 서버 로그의 보관도 별도 정책이다.

## 3. 계측 제공자 선택

Cloudflare Web Analytics는 계정과 JS snippet으로 방문·페이지 성능을 측정할 수
있다고 안내한다. 기본 방문 현황 후보이며 커스텀 이벤트 수집·개인 리텐션의 보장으로
해석하지 않는다. 출처: [공식 소개](https://developers.cloudflare.com/web-analytics/about/).

GA4는 별도 구현한 커스텀 이벤트를 수집할 수 있다. 밴픽 시작/완료 같은 퍼널이
필요한 후보지만 계정·설정·수집 동의·검증이 필요하다.
출처: [커스텀 이벤트 안내](https://support.google.com/analytics/answer/12229021?hl=en).

현재 권장 순서는 기본 방문 계측과 앱 내 이벤트 계약을 먼저 분리하고, 목적을 충족하는
제공자 하나를 선택하는 것이다. 이름이 다르다고 중복 스크립트를 모두 넣지 않는다.
어느 계정도 지금 연결하지 않았다. 제공자 선택·계정 설정 후 실제 수신을 확인해야 완료다.

Google Analytics는 PII 전송 금지와 URL·페이지 제목·입력값을 통한 누출 방지를
안내한다. 사용자 Riot ID·이메일·PUUID·개인 카드와 원본 전적을 이벤트나 URL에
넣지 않는 것이 이 프로젝트의 기준이다. 단순 해싱을 완전한 익명화라고 주장하지 않는다.
출처: [PII 방지 안내](https://support.google.com/analytics/answer/6366371?hl=en).

재방문 계측이 제한되어도 지문 채취로 이를 우회하지 않는다. 광고/분석 거부와
개인 전적 삭제를 별도로 제공하며 기본 밴픽은 계측 동의 여부와 무관하게 작동시킨다.
구체적 법정 보관·동의 의무는 운영 지역과 실제 데이터 흐름을 정한 뒤 확인한다.

## 4. 호스팅

현재 GitHub Pages는 정적 HTML/CSS/JS를 호스팅한다. 이 환경에서 비밀 API 키를
보관하는 서버 중계·RSO·비공개 데이터베이스·원격 방 서버까지 해결됐다고 볼 수 없다.
출처: [GitHub Pages 설명](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

GitHub는 Pages를 온라인 사업·상거래·상업 SaaS의 무료 호스팅 용도로 사용하는 데
제한을 둔다. 광고 하나가 있는 모든 페이지가 금지라고 단정하지 않지만, 이 제품의
상업 운영 목표에 맞는 호스팅인지 공개 전 확인하고 필요하면 이전한다.
출처: [Pages 사용 제한](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

| 필요 | 구조 | 아직 결정하지 않은 것 |
|---|---|---|
| 브라우저 밴픽/가벼운 엔진 | 정적 프런트 + CDN | 상업 운영 허용 호스팅·도메인 |
| 공식 API/본인 계정 | 프런트 + 비밀키 중계/인증 서버 | 제공자·운영 예산·삭제/보관 |
| 원격 양 팀 밴픽 | 권위 상태 서버 + 방별 접근 제어 | 방/동기화/재접속/운영 비용 |
| 무거운 시뮬레이션 | 제한된 작업 큐 + 모델/캐시 | 실행 한도·대기·비용 상한 |

첫 공개에 원격 방과 무거운 서버 모델을 모두 넣지 않는다. 실제 트래픽·사용 가치에
따라 확장한다. 공유 링크와 실시간 동시 접속 방은 다른 기능이다.

## 5. 광고와 자료 이용권

Riot의 개발 정책은 제품 등록과 Approved/Acknowledged 상태의 수익화 조건을
설명하며 무료 접근에 광고를 포함할 수 있게 한다. 같은 문서는 Riot IP 기반 게임과
유사 제품, 공식 랭크 대체 시스템 등에 제한도 둔다. 이 서비스는 분석 시뮬레이터로
설명하되 이름만으로 허용 범위가 확정되지는 않는다. 실제 기능과 사용 자산을
제품 페이지에 제시해 검토받는다. 내부 source ENABLED는 그 승인을 대체하지 않는다.
출처: [Riot 일반 정책](https://developer.riotgames.com/policies/general).

GRID 등 상세 데이터의 상업 이용권은 별도다. 광고 서비스에 사용하기 전
[API 조사 문서](API_DATA_RESEARCH_2026-11-17.md)의 출처별 조건을 확인한다.
실험용 무료 키·공개 사이트·API 제품 승인·모델 학습권을 같은 허가로 간주하지 않는다.

AdSense는 원본 콘텐츠와 정책 준수 등을 신청 요건으로 안내한다. 사이트를
배포했다는 이유로 승인이나 수익이 보장되지 않는다.
출처: [참여 요건](https://support.google.com/adsense/answer/9724?hl=en).

EEA·영국·스위스 방문자에게 개인 맞춤 광고를 제공할 때 Google 인증 CMP/TCF
요건을 안내한다. 운영 대상과 광고 방식이 정해지면 해당 설정과 안내를 확인한다.
출처: [게시자 동의 요건](https://support.google.com/adsense/answer/13554116?hl=en).

### 광고 위치와 제품 기준

- 데스크톱은 작업 영역 밖, 모바일은 밴픽 조작과 떨어진 하단 등 한 위치부터 검토한다.
- 챔피언 검색·확정 버튼·턴·픽 카드 위에 겹치거나 광고 클릭을 기능처럼 유도하지 않는다.
- 방송 보기에서는 광고 숨김 옵션과 실제 수익 영향을 함께 검토한다.
- 광고 거부·차단 상태에서도 밴픽과 로컬 파일이 깨지지 않아야 한다.
- 심사에 필요한 독자적 사용 가이드·한계·문의·출처·개인정보 안내는 상세 페이지에 둔다.
  메인을 설명문으로 채우거나 외부 콘텐츠를 얇게 복사하는 방식은 사용하지 않는다.

## 6. 수입과 비용 계산

페이지 기준 예상 수입 = 페이지 조회수 / 1,000 × 실제 관측 Page RPM.
RPM은 조회 가능한 실제 광고 보고서에서 가져오고 임의 단가를 확정하지 않는다.
광고 노출 기준 계산과 페이지 기준 계산을 섞어 같은 수입을 두 번 계산하지 않는다.

순수입은 광고 수입에서 호스팅·도메인·데이터 라이선스·작업 큐·저장·모델 호출 등
실제 비용을 빼서 판단한다. LLM을 매 클릭이나 매 시뮬레이션 판정에 반드시 호출하는
구조는 피하고 계산 엔진·캐시·선택적 해설로 분리한다. 손익분기 방문 수는 실제
계약과 관측 RPM이 생긴 뒤 계산한다. 월 수입을 현재 단계에서 약속하지 않는다.

## 7. 자동 진행과 사용자 결정

자동 진행: UI·문서·계측 어댑터 인터페이스·로컬 실행·테스트·샘플 기반 검증.
사용자 결정: 도메인 구매·유료 예산, Riot/GRID 등록·계약·키 발급, 광고 계정/정산,
개인정보 안내의 실제 운영자 정보와 공개 범위. 계정·결제 대신 가입하거나 외부에
허가 문의를 발송하는 것은 별도 명시 지시가 있어야 한다.

## 8. 운영 완료 증거

- 배포된 올바른 버전과 모바일/PC 핵심 동작 확인, 이전 버전 복구 가능.
- 개발·봇·중복·거부 상태를 포함한 계측 검증과 수신 확인.
- 기능 입력이나 개인 자료가 분석/광고 요청으로 나가지 않는 검사.
- 광고·API가 실패해도 기본 밴픽 정상 동작, 오래된 자료에 독립 시각 표시.
- 실제 사용량·오류·실행 시간·수입/비용을 같은 기간으로 확인하는 대시보드.

이 문서는 법적 허가나 광고 승인서가 아니라 공개 전 확인할 자료와 제품 설계다.
