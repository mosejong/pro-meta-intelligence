## 1. 사용자와 합의한 방향

- 특정 팀 저격을 종료한다. T1을 포함한 모든 팀은 동등한 선택 대상이다.
- 첫 화면은 모의 밴픽이다. 긴 설명·자료·분석은 상세 탭으로 보낸다.
- 친구·스트리머·일반 이용자는 로그인이나 JSON 편집 없이 시작할 수 있어야 한다.
- 시즌 중에는 대회 준비, 스토브리그에는 선수 교체·역대 시즌 구성 등 연중 이용 가치를 제공한다.
- 기능을 구현하고 검증한 뒤 완성된 기능부터 번역한다. **11/18 최신 결정: 한국어 지인 테스트판을 먼저 올려 수강생 동료·지인에게 사용 의견을 받는다.** 중국어 간체 완성과 중국 실제 접속 확인은 이후 중국 홍보/출시 관문이며 한국어 테스트판의 선행 조건이 아니다.
- 1인 개발자가 운영 가능한 범위를 유지한다. 광고 등으로 운영 흑자를 목표로 하지만 트래픽·수입을 예상 실적처럼 쓰지 않는다.
- 명칭·도메인 구매는 기능 완성 이후로 미룬다. 독립 매니지먼트 게임은 사용자 반응·수익성·권리 확인 이후 별도 검토한다.

기획 아이디어는 구현 승인과 구분한다. 실제 사용자 최신 지시가 이 문서보다 우선하며, 새 기획만으로 기존 수집·개발을 폐기하거나 전면 재설계하지 않는다.

## 2. 상태를 읽는 법

| 상태 | 의미 |
|---|---|
| 검증 완료·로컬 | 해당 변경에 대한 검사 증거가 있음. 공개 서비스 반영과 다름 |
| 코드 존재·검증 대기 | 구현 또는 산출물은 있으나 통합·호환·실제 조작 확인이 남음 |
| 진행 중 | 현재 개발/수집하는 범위. 완료 기능으로 홍보하지 않음 |
| 계획 | 기존 합의나 검토 대상. 실행·완료를 뜻하지 않음 |
| 미확인 | 코드·로그·실제 환경에서 확인하지 못함 |

개별 테스트 수를 더해 서비스 완성도나 정확도 백분율로 바꾸지 않는다. 단위 검사·브라우저 검사·실제 이용자 평가·운영 접속은 별개의 증거다. 과거 테스트 결과를 이후 미커밋 작업에 그대로 적용하지 않는다.

### 지금 진행 중인 작업

현재 원본으로 2022년 711개·2026년 473개, 총 1,184개 시즌 카드를 만들었다. 카드 단위는 출처·선수 ID·시즌·팀·역할이므로 선수 1,184명이라는 뜻이 아니다. 파생 파일은 약 1.23MB이며 원시 경기 행을 배포하는 파일이 아니다.

연결 코드는 현재 선수 슬롯과 별도의 시즌 참조를 저장한다. 과거 선수를 배정한 자리에 현재 선수가 남아 계산되는 일을 방지한다. 시즌 선수는 A/B의 선수 효과나 경기 엔진에 연결하지 않았다. 최신 main 통합 전 웹219/219·PC/모바일14/14 등 [해당 범위 검사](SEASON_LINEUP_RESULT_2026-11-18.md)를 통과했다.

다음 배포 관문과 유지할 검사:

1. 구단 저장 v1 → v2 호환, 미지원 버전 거부, 시즌 참조 유실·중복·자료 교체 검사.
2. 새 시즌 JSON의 명시적 Git 추적·정적 배포 포함을 유지하고 실제 서비스 URL에서 확인.
3. 현재 선수/시즌 선수 선택·해제, 저장·새로고침·확인/취소, 상대 중복의 PC·모바일 통합 검사.
4. 과거 선수가 미지원 분석 입력에서 현재 선수로 치환되거나 정상 지원으로 오표시되지 않는지 확인.
5. 파생 자료 갱신 시 카탈로그 참조를 자동 교체하지 않고 기존 저장을 보존하는 흐름 검증.

## 4. 자료와 시스템

### 확보 범위

- 주요 출처는 Oracle's Elixir 공개 CSV, Riot Data Dragon의 승인된 정적 정보, 기존 공식 일정 어댑터다. 저장소 내부 허용 상태는 Riot의 제품 승인이나 상업 이용 허가가 아니다.
- 2014~2026년의 정확한 연도별 파일 목록을 등록했다. **로컬 원본 확보 연도는 2022·2026이며 전체 연도 수집 완료가 아니다.**
- 현재 시즌 자료에 LCK·LPL·LEC·LCS·국제대회 등이 포함되지만 리그·연도별 전체 경기/선수 완전성을 보장하지 않는다.
- 2022 Nuguri 57경기는 독립 집계와 대조했다. 그 기록에서 현재 복귀·소속·현 패치 능력을 추론하지 않는다.
- 새 원본 수집은 승인된 파일 ID·출처 정책·해시·실제 취득 시각·요청 간격을 유지한다. 로컬과 호스팅 수집기의 예산 조정도 운영 관문이다. 원본 CSV를 웹/git으로 재배포하지 않는다.
- Riot Web API는 `REVIEW_REQUIRED`이며 활성화하지 않았다. 개인 솔로랭크와 비공개 스크림을 이미 수집하는 것으로 설명하지 않는다.

원본의 당시 명칭·시즌·패치와 현재 명칭을 자동으로 같게 취급하지 않는다. 미확보, 확보 범위 내 미관측, 실제 관측을 구분하며 미관측을 숙련도 0으로 바꾸지 않는다. [세부 경계](HISTORICAL_PLAYER_SCENARIOS.md), [출처 정책](SOURCE_REGISTRY.md)

```text
실시간 밴픽: 별도 Node HTTP 서버의 임시 메모리
```

운영용 관계형 DB·계정 서버는 아직 연결하지 않았다. 기존 파일 집계를 버리고 DB부터 새로 만들지 않는다. 영속 구단·방 복구·인증이 필요해지는 단계에서 저장 계층을 추가한다. 임시 방은 2시간 만료/재시작 소멸하며 공개 운영·외부망·실제 휴대폰 검증을 대체하지 않는다.

## 5. 분석·예측·재미 기능의 경계

**관측 성향**은 특정 범위의 챔피언 사용 횟수·역할·밴 습관이다. **능력치**는 별도 정의와 평가가 필요한 추정값이다. **시뮬레이션 결과**는 모델 규칙·입력 안의 결과다. 어느 것도 자동으로 실제 승률이나 인과 효과가 되지 않는다.

현재 실험 엔진은 사용자가 설정한 라인·템포·한타 가정과 시드로 추상 자원/교전/오브젝트/기지 이벤트를 만든다. 실제 패치·선수·챔피언·룬·아이템 효과를 학습한 엔진이 아니다. 승자가 출력된다는 이유로 실전 예측이라고 표시하지 않는다.

기존 회고 평가에서 선수 시즌 기록 혼합의 추가 효과는 입증되지 않았다. 573경기 공통 지원 표본의 픽 적중률은 같은 리그·역할 메타 55.87%, 시즌 혼합 55.45%였으며 차이 구간에 0이 포함됐다. 이 값은 경기 승률 예측 정확도나 이용자 효용이 아니다. [실험 조건과 한계](SCOUTING_EVIDENCE_BENCHMARK_RESULT.md)

실제 경기 예측을 목표로 바꾸려면 경기 전 시점 자료, 누출 방지, 기본 모델, 분리 평가, 확률 보정·불확실성을 별도로 검증한다. 인간의 의사결정 개선은 실제 사용자 평가로 확인하며 에이전트 리허설로 대신하지 않는다.

## 8. 출시·사업·정책 관문

첫 사업 가설은 로그인 없이 쉽게 반복하는 밴픽·팀 구성 웹서비스다. 첫 방문 이후 밴픽 시작/완료, 방 생성, 저장, 비교·재도전, 재방문, 오류와 실제 인프라 비용을 확인한다. 다른 서비스의 동접은 참고 사례이며 우리 수요·매출의 증거가 아니다. 계측 제공자 수신과 광고 실적은 미확인이다.

공개 후 국가별 집계 이용 현황으로 투자·홍보를 판단한다. 언어 선택을 실제 국가로 간주하지 않으며 개인 계정 기록과 트래픽 집계를 결합하지 않는다. 중국어 번역과 중국 실제 이용 가능성·현지 운영 요건은 별개의 확인이다. 현재 중국 내 운영 요건 충족은 미확인이다.

2026-11-18 열람한 [Riot 개발자 정책](https://developer.riotgames.com/policies/general)은 Riot IP를 사용한 게임 개발 금지와 제품 등록·수익화 조건을 명시한다. [IP 이용 정책](https://www.riotgames.com/en/legal)도 별도로 적용 범위를 확인해야 한다. **‘시뮬레이터’라는 명칭이나 별도 사업 분리만으로 허용되는 것은 아니다.** 게임에 가까운 기능을 개발·공개하기 전 실제 화면·사용 자산·기능·수익화 방식을 기준으로 허용 여부를 확인한다.

팀 로고·선수 이미지·데이터 제공자 조건·상업 이용·중국 운영 관련 사항도 실제 사용 범위별로 검증한다. 내부 출처 레지스트리, MIT 코드 라이선스, 정적 CDN 접근 가능 여부는 타인의 데이터·IP 사용 권리를 대신하지 않는다. 정책은 출시 시 다시 확인한다.

## 9. 의사결정과 변경 관리

현재 보존할 순서는 시즌 연결 → 핵심 흐름 검증이다. 다음 결정은 해당 단계 직전에 묶어서 요청한다.

- 시뮬레이션 목적: 재미를 위한 가정 실험 / 실제 경기 예측. 둘을 같은 검증으로 취급하지 않음.

- 운영 제공자·비용·보관/삭제·외부 계정·도메인·콜백 설정.

새 제안은 `이미 구현 / 진행 중 / 기존 계획 / 신규 제안 / 설계 변경 / 보류 / 충돌·확인`으로 분류하고, 근거·영향·재사용할 코드·승인 필요 여부를 남긴다. 분석만 요청받은 턴에는 코드·DB·기능·커밋·배포를 변경하지 않는다. 이번 문서 작성은 기능 개발 재개 승인으로 해석하지 않는다.
