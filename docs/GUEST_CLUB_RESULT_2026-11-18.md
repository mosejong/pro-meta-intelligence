# 게스트 구단 작업 결과

2026-11-18. 이름 붙인 선수 구성을 기기에 저장하고 불러오는 v1을 구현했다. 공개 사이트 배포·OAuth·서버 저장은 실행하지 않았다.

## 구현 범위

`선수·로스터` 탭 위에 내 구단을 추가했다. 블루/레드 중 하나의 5역할 선수·빈 자리와 구단 이름을 저장하며, 감독·코치는 접힌 선택 항목에서 직접 적는다. 최대 10개. 불러오기 전 선수 미리보기·적용 진영을 확인하고 취소할 수 있다. 삭제 확인은 현재 로스터를 지우지 않는다. 저장·복원은 JSON 편집 없이 버튼으로 이용한다.

상대와 선수 ID 중복, 알 수 없는 선수, 자료 기준 변경, 손상·미지원 저장 형식, 저장소 거부/용량 초과 시 기존 데이터를 보존한다. 다른 탭에서 구단이 바뀌면 갱신한다. 저장/삭제는 Web Locks로 직렬화하며 지원하지 않는 브라우저에서는 안내하고 저장을 중단한다.

## 검증 증거

- 전체 웹 테스트 212/212 통과. 탭 간 lock 최종 보완 전 실행이며 이후 변경은 아래 범위로 재검증했다.
- 최종 타입 검사·ESLint 통과.
- 최종 구단 단위 8개와 일반 Pages 4개: 12/12 통과.
- 최종 실제 Chrome PC/모바일 구단 검사 8/8 통과: 저장·새로고침 복원·빈 자리·불러오기/삭제 취소·저장소 장애·손상 저장 보존·두 탭 동시 저장.
- 최초 브라우저 실행에서 진영 선택의 접근성 이름을 정확히 찾지 못해 검사가 멈췄다. 실행을 중단하고 선택 상자에 명시적인 이름을 추가한 뒤 최종 8개를 통과했다. 성공 화면을 PC/모바일로 저장하고 모바일 이미지를 열어 배치를 확인했다.
- 별도 읽기 전용 검토에서 탭 간 read-modify-write 경합 P2 한 건을 찾았다. Web Locks 및 lock 안 최신 읽기로 보완하고 실제 두 탭 동시 저장을 PC/모바일에서 검증했다.

로그: `outputs/guest-club-{web-full,typecheck,lint,final-unit-pages,e2e}-20261118.log`. 성공 화면: `outputs/guest-club-{desktop,mobile}-20261118.png`.

기존 로스터 브라우저 회귀도 PC/모바일 10/10 통과했다. 선수 이동·진영 교환·새로고침 복원·기준 A 보존·v3 내보내기/읽기 전용 복원·지연 파일 읽기·손상 파일 거부를 확인했다. 로그는 `outputs/guest-club-roster-regression-20261118.log`다. Python 코드는 변경하지 않았고 재검사하지 않았다.

## 남은 범위

클라우드 계정 귀속, 구단명으로 실제 팀 교체, 코치 명단/능력, 선수 시즌 카드, 자료 갱신 시 명시적 재연결, 구단 파일 내보내기, 구단·선수의 실시간 방 공유는 미구현이다. 기존 로스터 파일 저장은 유지한다. 현재 구단 적용은 로스터 편집과 A/B 입력만 바꾸며 추천 순위나 실제 승률을 바꾸지 않는다. 계정이나 기기 간 저장으로 표현하지 않는다.
